# SNES YACHT Implementation Plan

> **Since v1.1:** the straights are Small (any four in a row, 30) and Large (five in a row, 40), not Yacht's Little/Big; X rolls and A holds; "Four alike!" is spoken. See `snes/yacht/README.txt`.

> Layout note: written when this work lived in a Tandy repo as `yacht/` and `snes/`. In this repo those are `tandy1000/yacht/` and `snes/yacht/`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `snes/build/yacht.sfc`, a SNES port of the Tandy 1000 YACHT game that plays identically and looks and sounds like a polished SNES title.

**Architecture:**
- 65816 game code and an SPC700 sound driver, both hand-written and
  assembled with WLA-DX into a 512 KB LoROM with 2 KB of battery save RAM.
- All graphics, instruments, music and voice data are generated by Node
  scripts in `snes/tools/`, drawn in code with built-in modules only.
- Tests run in Mesen 2's headless test runner with Lua scripts. Asset
  tools have `node --test` unit tests.

**Tech Stack:**
- WLA-DX v10.7: `wla-65816`, `wla-spc700`, `wlalink`.
- Mesen 2.1.1 (portable, Lua file access enabled).
- Node 26.
- Windows SAPI for voice.
- Git Bash `build.sh`.

**Spec:** `docs/superpowers/specs/2026-11-14-snes-yacht-design.md`. Source game: `yacht/src/*.asm`.

## Global Constraints

- **Tool paths:**
  - `W=$HOME/tools/wla-dx/wla_dx_v10.7_Win64`
  - `MESEN=$HOME/tools/mesen2/Mesen.exe`
  - Both live outside the repo.
- **Cartridge header:**
  - LoROM, SlowROM, map mode `$20`, cartridge type `$02`, ROM size code
    `$09` (512 KB), SRAM size code `$01` (2 KB), country `$01` (NTSC USA).
  - Title `YACHT`, padded with spaces to 21 chars.
  - `.COMPUTESNESCHECKSUM`. No copier header.
- **Mesen Lua:**
  - Relative paths resolve to Mesen's folder, so every file path in a test
    script is absolute. They're built from `TEST_OUT`, set at the top of
    each script by `snes/tests/run.sh` through a generated prelude.
  - Exit with `emu.stop(0)` for pass and a non-zero code for fail.
- **Register convention:** outside NMI and init, code runs with A 8-bit,
  X/Y 16-bit (`sep #$20 / rep #$10`), direct page `$0000`, data bank `$00`
  (low RAM mirrors). Any routine that changes this restores it before
  `rts`.
- **Uninitialized memory:** init clears all WRAM, VRAM, CGRAM, OAM and APU
  ports before use. Tests run with Mesen set to random power-on RAM
  (`run.sh` sets this in `settings.json` before each run).
- **Rules:** identical to `yacht/src/yacht.asm` `score_cat` (lines
  1014–1101):
  - Faces score face × count.
  - Full House scores the sum, but only for an exact 3+2.
  - Four of a Kind scores 4 × the face, when the count is at least 4.
  - Little Straight (1–5) and Big Straight (2–6) score 30.
  - Choice scores the sum.
  - Yacht scores 50.
  - No bonus, and the total is the sum of filled boxes.
- **Skipper:** a line-by-line translation of `yacht/src/game.asm`
  `ai_turn` through `ai_holds` (lines 862–1127) plus `ai_expect` in
  `data.asm`. Ties go to the first box.
- **Best score:** counts human scores only.
  - Against the Skipper, it's the human's total.
  - With two players, it's the higher total.
  - The demo game never counts.
- **Sound rules from the source:**
  - A zero score plays `tune_bad`.
  - Mute also silences the voice.
  - "Straight!" plays only when the score is above 0.
- **No npm dependencies.** Node built-ins only.
- **Commits:** no commits without the owner's say-so. Each task ends with
  a "checkpoint" step that stages the files and reports. Commit only if the
  owner has OK'd committing.

## Review Focus

1. **Controller 2 not plugged in during a two-player game.** Controller 1
   must play both turns. Test it in Task 7 with a run that sends no
   port-2 input.
2. **Pressing buttons during the tumble, the Skipper's turn or a voice
   upload.** Input must be ignored or queued, never cause a double roll or
   a lockup. Test it in Task 7 by mashing A every frame through a whole
   Skipper turn.
3. **Corrupt or blank save RAM on first boot** (on the real cart, blank
   save RAM is random). The game must reset to defaults and not show a
   garbage best score. Test it in Task 8 by writing random bytes before
   boot.
4. **Game over after a turn of all zeros.** For example, scoring 0 in
   Yacht: the right tune must play, the total stays correct, and the board
   still fills. Test it in Task 7 with a seeded game where a zero is scored.
5. **Muting in the middle of a voice clip.** The voice stops at once, and
   the next clip doesn't play while muted. Test it in Task 9 by checking
   key-off and the driver's state bytes after mute.

## Shared interfaces (used across tasks)

**Variables, in `vars.inc`, all in low WRAM:**
- `frame` (u16): the frame counter.
- `pad1`, `pad2` (u16): held buttons, raw SNES bit layout.
- `pad1_new`, `pad2_new` (u16): buttons newly pressed this frame.
- `dice` (5 bytes, faces 1–6, 0 = blank), `held` (5 bytes, 0/1),
  `rolls_left` (u8).
- `scores`: 2×12 u16, with `$FFFF` meaning empty. Player 0's boxes come
  first, matching the Tandy layout.
- `cur` (u8, the player on turn), `game_mode` (u8: 0 = two players, 1 =
  vs Skipper, 2 = demo; same values as the Tandy).
- `best` (u16), `muted` (u8), `seed` (u16).
- `test_result` at fixed address `$7E1F00`:
  - u16 `$5A5A` once the self-test is done;
  - then u16 checks run, u16 failures.
- `oracle` at fixed address `$7E1F10`:
  - u8 command: 1 = score, 2 = AI;
  - 5 dice;
  - u8 rolls left;
  - 12 bytes open flags;
  - outputs: 12×u16 scores, 5 bytes of holds, u8 pick, u8 satisfied, then
    u8 done = `$A5`.
- `test_seed` at fixed address `$7E1F80`: u16. If it's non-zero at boot,
  the RNG uses it instead of the frame and input entropy.

**Routines, using the register convention:**
- `ScoreCat`: A = category 0–11 → result in `res16`. Uses `dice`.
- `PlayerTotal`: A = player → `res16`.
- `BoardFull`: carry set when every box of both players is filled.
- `FirstOpen`: A = player → A = first empty category.
- `Roll1`: → A = a random face 1–6.
- `RngNext`: → A (16-bit result in `res16`).
- `SkipperTurnStep`: called once per frame during the Skipper's turn. It
  advances the turn's state machine and sets `turn_done` when the box is
  scored.
- `SkipperHolds`: sets `held[]` from `dice` and `rolls_left`.
- `SkipperPick`: → A = the category to score.
- `SkipperSatisfied`: carry set when it should stop rolling.
- `AudioCmd`: A = command, X = argument.
  - Commands: `AC_MUSIC` (X = tune id), `AC_SFX` (X = sfx id), `AC_VOICE`
    (X = clip id), `AC_STOP`, `AC_MUTE` (X = 0/1).
  - Tune ids, in order: title, score, bad, good, yacht, win, lose.
  - Clip ids follow the order of `yacht/tools/speech.txt`.
- `VramQueue`: queues a DMA of X = source address (24-bit in
  `dma_src`/`dma_bank`), Y = VRAM word address, `dma_len` bytes. It's
  flushed in NMI.
- `PrintAt`: X = pointer to a zero-terminated string, Y = BG3 tile index
  (row × 32 + column), A = palette.

### Task 9: Sound: SPC700 driver, music, effects, voice

**Files:**
- Create:
  - `snes/src/spc/driver.s`, `snes/src/audio.s`
  - `snes/tools/instruments.js`, `tunes.js`, `speech.sh`, `voice.js`
  - `snes/tests/audio.lua`
- Modify: `snes/build.sh`

**Interfaces:**
- Consumes: `brr.js`.
- Produces: the real `AudioCmd`, replacing the stub.
- **Driver protocol, over ports `$2140`–`$2143`:**
  - port 0 carries the command, with a toggling sequence bit;
  - ports 1–2 carry the argument;
  - the driver echoes the sequence on port 0 when done.
- **Voice upload:** `AC_VOICE` first streams the clip's BRR into the 16 KB
  voice buffer at ARAM `$8000`, through a block-transfer command, then
  starts voice channel 7.
- **Driver state:** at ARAM `$00F0`–`$00F7`:
  - playing tune;
  - voice active;
  - muted;
  - key-on mask.

- [ ] **Step 1: Write `audio.lua`**
  - After the title starts, `emu.read(0xF0, emu.memType.spcRam)` = the
    title tune id.
  - Trigger a voice (via `apply_score` with a scripted Yacht, or a debug
    hook) → voice active = 1.
  - Toggle mute with Select → within 2 frames, voice active = 0, muted = 1,
    and DSP KON shows nothing new. Then trigger another voice → it stays 0.
- [ ] **Step 2: Implement the driver**
  - 6 music channels, channels 6–7 for effects and voice;
  - envelope per instrument;
  - a tick at 125 Hz from SPC timer 0;
  - note data from `tunes.js`, which parses `yacht/src/data.asm` for the
    `tune_*` tables, the `MEL_*` macros and `N_xx`/`LEN_xx` pairs, then
    remaps them to the driver's pitch table.
- [ ] **Step 3: Generate the sounds.**
  - `instruments.js` synthesizes:
    - mellow marimba, steel drum and soft bass (looped, 32 kHz → BRR);
    - dice rattle, click, tick and chime effects.
  - `speech.sh` renders `yacht/tools/speech.txt` with the Microsoft David
    voice at 32 kHz, 16-bit, into `build/speech/`.
  - `voice.js` resamples it to 12 kHz with a low-pass filter, normalizes
    to −1 dBFS, and BRR-encodes it.
  - The build fails if any clip is over 16 KB.
- [ ] **Step 4: Run `run.sh audio`, then all tests.** Expected: all PASS.
- [ ] **Step 5: Listening check.** Dump each tune and clip to WAV by
  decoding the BRR with `brr.decode` and mixing in Node:
